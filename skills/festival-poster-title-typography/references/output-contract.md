# 输出协议

根据调用者选择一种形式，不需要同时输出所有形式。

## A. 面向用户的设计方案

保持紧凑，包含：

1. **匹配结论**：主原型 ID、名称及一句理由。
2. **标题字规范**：原文、横竖结构、骨架、笔势、纹理、颜色/效果、落位与尺寸关系。
3. **生成提示词**：可直接交给图像生成或字效制作流程的一段提示词。
4. **避坑**：最多三条与当前画面直接相关的负面约束。

若用户要比较方案，给一个主方案和一个明确不同的备选即可，并说明取舍。

## B. 供上游海报 Skill 消费的 JSON

当用户要求机器可读结果，或本 Skill 被当作海报生成流程的标题模块时，只返回合法 JSON，不加 Markdown 围栏：

```json
{
  "title_text": "惊蛰",
  "style_id": "T06",
  "style_name": "水墨光笔",
  "match_reason": "湿润森林、晨光与惊雷动势适合带长收笔的冷白湿墨字",
  "orientation": "vertical",
  "line_break": ["惊", "蛰"],
  "glyph_skeleton": "挥写感行草，主笔清晰，字形不可误连",
  "stroke_and_texture": "湿笔边缘、少量水雾颗粒、单条长收笔",
  "fill_color": "#EAFBFF",
  "secondary_color": "#8EDFFF",
  "effects": ["窄幅内发光", "低半径柔光"],
  "semantic_inlay": "none",
  "placement": {
    "zone": "upper_left",
    "alignment": "top_to_bottom",
    "frame_width_ratio": 0.20,
    "clearance": "避开主体头部、蕨叶主脉和品牌标志"
  },
  "generation_prompt": "……",
  "negative_constraints": [
    "汉字必须严格为惊蛰",
    "不要额外文字、Logo、二维码或场景元素",
    "不要粗霓虹描边，不让长尾连接成伪汉字"
  ],
  "confidence": 0.91
}
```

字段规则：

- `title_text` 必须与用户原文完全一致。
- `style_id` 只能是 T01–T08；若用了次级修饰，在 `stroke_and_texture` 或 `effects` 中说明，不另造 ID。
- `orientation` 使用 `horizontal`、`vertical` 或 `two-line`。
- `line_break` 按真实阅读单元给出，不把一个汉字拆开。
- `frame_width_ratio` 为标题字组占整张海报宽度的估计值，范围 0–1。
- `semantic_inlay` 没有融合符号时写 `none`。
- `confidence` 是匹配判断信心，不是生成成功概率。

## C. 独立标题字素材

直接调用图像生成交付一张不含场景的原创标题字图层，并在回复中明确：文件格式、画布尺寸、背景是否透明、标题逐字校对结果、推荐落位。不得使用本地或系统字体作为字骨、参考图或最终回退。若透明失败，只接受单一高饱和纯色键底并明确抠取方式；假透明棋盘格、渐变底和纸张底均判定失败。

## 生成提示词公式

提示词使用一段自然语言，并按以下顺序组织：

`精确标题原文 → 主原型与字形骨架 → 横竖/行列结构 → 笔势和边缘 → 材质与语义修饰 → 主辅颜色和光效 → 独立素材要求 → 逐字正确与禁止项`

模板：

> 只设计中文标题“{原文}”，采用{原型}的{骨架描述}，{横竖结构与字序}；笔画{粗细、速度、收笔}，边缘{纹理}，结合{最多一个场景语义修饰}；主色{颜色}，仅使用{克制特效}。输出独立标题字素材，透明背景或高反差纯色背景，画面中不得出现人物、动物、景物、Logo、二维码、副标题或额外字符。所有汉字必须严格、清晰、完整地写成“{原文}”，不得错字、增字、缺字或伪汉字。

图像模型第一次生成的中文不应被默认视为正确。必须与 `title_text` 逐字比较；错字、增字、缺字、伪字、误连、脏底或缩略图不可读时，只允许一次针对性重生。第二次仍失败时明确报告，不得改用本地字体、系统字体、SVG 字骨或确定性排字兜底。
